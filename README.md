## My principles

- **Write for the next person.** Prefer clear names, focused methods, and straightforward code. Document decisions that need context.
- **Start with the user's workflow.** An API, background job, or admin form should make a real task easier to complete. Think through validation, feedback, and failure states alongside the happy path.
- **Test behavior that matters.** Use RSpec and Capybara to protect business rules and important user journeys, especially around subscriptions, publishing, and scheduled work.
- **Keep complexity justified.** Choose maintainable solutions that fit the problem. Improve the design as requirements become clearer.
- **Think beyond the request.** Consider background processing, time zones, external-service failures, and deployment when building a feature.
- **Communicate clearly.** Make assumptions explicit, raise questions early, and leave enough context for teammates to continue the work.
